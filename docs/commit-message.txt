elanmoc2: Fix use-after-free and double-report on verify retry

Two bugs in the identify/verify error path crashed fprintd on every
finger press once a retry (e.g. "press harder" / "sensor is dirty or
wet") was reported:

1. elanmoc2_identify_verify_report() passed the GError to
   fpi_device_verify_report() by value while the caller kept a
   g_autoptr(GError) that freed it right after. fprintd later reads
   error->message in verify_cb()'s g_warning() and dereferences the
   freed error (SEGV in g_strdup_vprintf).

2. The retry branch jumped back into the SSM
   (fpi_ssm_jump_to_state(ssm, IDENTIFY_IDENTIFY)) instead of
   finishing the action. On the next press the driver reported a
   second time, tripping fpi_device_verify_report()'s
   result_reported == FALSE assertion.

Fix:
- Report an error as FPI_MATCH_ERROR and transfer ownership of the
  error to the core with g_steal_pointer() (both the verify and the
  identify branch).
- On a retryable error, report the retry error and complete the
  action (fpi_device_verify_complete + fpi_ssm_mark_completed), the
  same pattern the older elanmoc driver uses. The core then ends the
  task with the retry error and fprintd restarts the verify with a
  fresh task.

Verified on an ELAN 04f3:0c00 (HP Pavilion Aero 13): verify now
returns retry errors cleanly (verify-remove-and-retry) and completes
with verify-match, with no assertion and no crash. Also verified
deterministically with the umockdev pcapng replay in tests/elanmoc2
under G_DEBUG=fatal-warnings.
